# [AL.M.004] Поддержка самонаправленного обучения

## Definition and purpose

Метод соотносит степень директивности, доступный выбор, опоры и обратную связь с текущим предметным знанием и наблюдаемым выполнением конкретных компонентов. Поддержка проходит цикл: распознать затруднение → оценить возможный вред и обратимость → выполнить разумную попытку или немедленно эскалировать → запросить минимально достаточную помощь → переработать её → выполнить новую пробу → снять, вернуть или изменить помощь → передать ответственность. Для существенной угрозы заранее задаются право остановки в пределах роли, первичный адресат, следующий уровень и срок подтверждения.

## Forces

| Force | Tension |
|---|---|
| Автономия ↔ опора | Недостаток структуры перегружает; избыток подавляет субъектность |
| Единый результат ↔ вариативный путь | Критерии сохраняются при разных маршрутах |
| Гибкость ↔ обязательства | Маршрут можно менять, но изменения должны быть обоснованы |
| Текущее выполнение ↔ самостоятельная способность | Помощь может улучшать пробу, не создавая способности действовать без неё |
| Избегание помощи ↔ замещение действия | Участник может слишком долго действовать без нужной помощи либо преждевременно запросить готовое решение |
| Попытка ↔ немедленная эскалация | Самостоятельная проба полезна в безопасной задаче, но недопустима при высокой цене ошибки |
| Межличностная безопасность ↔ предметная ответственность | Защита добросовестного вопроса и предупреждения не отменяет стандартов, проверки и последствий сознательного нарушения |

## Key distinctions and bias

- AL.D.002: принцип ≠ закон.
- AL.D.009: персонализация ≠ бесконтрольный выбор.
- **Bias:** культ автономии — проектировщик преждевременно снимает поддержку, считая взрослость достаточным признаком готовности.
- **Bias:** постоянная помощь — проектировщик сохраняет подсказки после того, как они перестали помогать обучению и начали скрывать самостоятельность.
- **Bias:** частотная оценка — число вопросов принимается за качество саморегуляции без данных о необходимости, попытке, уровне помощи и следующем действии.

## Failure modes

AL.FM.002, AL.FM.009.

## SoTA

`current` как адаптивный принцип. Поддержка снимается и при необходимости возвращается по данным выполнения конкретного компонента, а не по возрасту, общей самооценке, числу запросов или календарю курса. Поиск помощи рассматривается как навык саморегуляции; продуктивность определяется сохранением ключевого действия за участником и новой пробой. При угрозе запрос помощи отличается от предупреждения и эскалации; проектный протокол канала, полномочий и замкнутой реакции принят как `current-practice`. Основания — AL.SOTA.011–014, STH.HS.CLAIM.001–007 и STH.PS.CLAIM.001–009. Конкретные пороги запроса и эскалации требуют проверки по типу риска.
